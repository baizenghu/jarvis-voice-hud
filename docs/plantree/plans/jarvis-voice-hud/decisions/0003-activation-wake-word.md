# 决策 0003 —— 唤醒方式 = 语音热词(喊它名字)

日期:2026-06-11。状态:已采纳。

## 背景
用户确认最终运行时为 Windows,并且助手通过**说出它的名字**来唤醒("唤醒 语音直接喊名字"),
而非热键。这让常驻热词监听成为核心功能,而非初稿里那个延后的阶段。

## 决策
- 主唤醒:一个常驻本地**热词监听器**,被助手的名字触发。命中后驱动 HUD 状态机的
  IDLE→LISTENING 迁移。
- 热键 / 点击 HUD **仅作开发期兜底**(让 Phase 0/1 在热词模型就绪前先跑通回路),不是出厂交互。
- **名字 = "贾维斯",中文喊。** 引擎 = **openWakeWord**:用合成(TTS)语音离线训练一个中文自定义
  热词,纯本地、免费运行。否决 Porcupine —— 它对中文自定义关键词支持弱。监听器跑在哪
  (浏览器 WASM vs Tauri Rust)仍未定 —— 见 open-question 2。

## 后果
- 唤醒词从"延后"升为路线图里已确认的阶段。
- 需要一条常驻监听的音频路径;倾向把监听器放在 Tauri Rust 侧,这样 WebView 隐藏/休眠也能存活
  (open-question 2)。
- 增加一条隐私说明:麦克风被本地持续采样以检测热词(名字命中前没有音频离开本机)—— 值得在
  面向用户的文档里讲明。

## 取代
初稿里把唤醒词当作可选 Phase 3 的处理(见 roadmap"延后")。
